# เผยแพร่ภาพกิจกรรมไปยัง Facebook Page

## การใช้งาน

1. เลือกภาพจากหน้าอัลบั้มหรือปุ่มอัปโหลดจากหน้ารวม
2. เปิด **เผยแพร่ไปยัง Facebook ด้วย** (ค่าเริ่มต้นปิดทุกครั้ง)
3. ติ๊กภาพที่ต้องการส่งขึ้นเพจ ตัวนับแสดงจำนวนที่เลือก พร้อมปุ่มเลือกทั้งหมดและล้างที่เลือก
4. กรอกคำบรรยาย หรือเว้นว่างเพื่อใช้ชื่อและคำอธิบายกิจกรรม
5. กดอัปโหลด ภาพทั้งหมดเก็บใน bpdactivity ส่วนภาพที่ติ๊กจะเข้าคิว Facebook หลังอัปโหลดครบ

เลือกส่งได้ 1–1,000 ภาพต่อชุด ระบบแบ่งโพสต์ละ 10 ภาพ และแสดงจำนวนโพสต์ก่อนยืนยัน ภาพที่ไม่ได้ติ๊กไม่ส่งขึ้น Facebook หากภาพที่ติ๊กบางภาพอัปโหลดไม่สำเร็จ จะไม่เผยแพร่ชุดนั้นโดยอัตโนมัติ

เฉพาะเจ้าของอัลบั้มหรือผู้ดูแล/ผู้บริหารเท่านั้นที่สั่งเผยแพร่ได้ และอัลบั้มต้องเป็น **สาธารณะ** ระบบตรวจสิทธิ์และการมองเห็นซ้ำก่อนส่ง ภาพยังถูกส่งขึ้น Facebook จริงผ่าน multipart upload ไม่ใช่เพียงโพสต์ลิงก์

## เชื่อมต่อเพจครั้งแรก

ผู้ดูแลสร้าง/ใช้ Meta App และขอ Page access token ที่เผยแพร่เนื้อหาบนเพจเป้าหมายได้ โดยบัญชีผู้อนุญาตต้องมีสิทธิ์สร้างเนื้อหาเพจ สิทธิ์ที่ใช้โดยทั่วไปคือ `pages_manage_posts`, `pages_read_engagement` และ `pages_show_list` การอนุมัติแอป/ธุรกิจขึ้นกับรูปแบบการใช้งานและสิทธิ์ของแอป

อ้างอิงเอกสาร Meta (ต้องตรวจตามเวอร์ชันและการตั้งค่าแอป):

- https://developers.facebook.com/docs/pages-api/posts/
- https://developers.facebook.com/docs/graph-api/reference/page/photos/

Cloudflare → Worker **bpdactivity** → Settings → Variables and Secrets:

| ชื่อ | ประเภท | ค่า |
|---|---|---|
| `FACEBOOK_PAGE_ID` | Variable | รหัสตัวเลขของเพจเป้าหมาย |
| `FACEBOOK_PAGE_ACCESS_TOKEN` | Secret | Page access token ที่ผู้ดูแลอนุญาต |
| `FACEBOOK_PAGE_NAME` | Variable (ไม่บังคับ) | ชื่อเพจที่แสดงในฟอร์ม |
| `FACEBOOK_GRAPH_VERSION` | Variable (ไม่บังคับ) | ค่าเริ่มต้น `v25.0` ปรับเมื่อทดสอบเวอร์ชันใหม่แล้ว |

Deploy ใหม่หลังตั้งค่า ห้ามใส่ token ใน Git, D1, หน้าเว็บ หรือข้อความแชท เมื่อยังไม่ตั้งค่า สวิตช์ Facebook ปิดใช้งานและอัปโหลดเข้า bpdactivity ได้ตามเดิม ไม่มีการส่งภาพเก่าย้อนหลังเมื่อเชื่อมต่อภายหลัง

หลังเชื่อมต่อ ให้ทดสอบด้วยอัลบั้มสาธารณะของผู้ดูแล เลือกหนึ่งภาพและตรวจทั้งสถานะบนเว็บกับโพสต์จริงก่อนเริ่มใช้งานทั่วไป

## คิวและผลลัพธ์

- ใช้ cron เดิมทุกนาที และเริ่มส่งในเบื้องหลังหลังยืนยันชุดอัปโหลด หน้าเว็บไม่ต้องรอ Facebook
- แต่ละรอบประมวลผลหนึ่งโพสต์ตามเวลาและสิทธิ์ปัจจุบัน อัลบั้มใหญ่จึงใช้เวลาหลายนาที
- เก็บรูปที่เลือกและรหัสรูปชั่วคราวจาก Facebook แยกจากโพสต์จริง ใช้ lock และคีย์ชุดอัปโหลดป้องกันทำงานซ้อน
- หน้าอัลบั้มแสดงรอส่ง/กำลังส่ง/เผยแพร่แล้ว/ส่งไม่สำเร็จ พร้อมลิงก์ดูโพสต์และปุ่มลองส่งใหม่สำหรับผลที่ยืนยันว่าล้มเหลว
- หากเครือข่ายขาดหรือ Worker หยุดขณะส่งโพสต์สุดท้าย สถานะเป็น **ต้องตรวจสอบบนเพจ** และไม่ส่งซ้ำอัตโนมัติ เพื่อหลีกเลี่ยงโพสต์ซ้ำ
- เมื่อเผยแพร่แล้ว การแก้/ลบอัลบั้มหรือเปลี่ยน Audience ใน bpdactivity ไม่แก้/ลบโพสต์เดิมบน Facebook ผู้ดูแลต้องจัดการโพสต์นั้นบน Facebook
- ไฟล์ JPEG/PNG/GIF/BMP/TIFF ไม่เกิน 10 MB ส่งจาก Drive โดยตรง ไฟล์ชนิดอื่นหรือไฟล์ใหญ่ใช้ภาพแปลงจาก Drive ที่ขนาด 2048 หากยังไม่พร้อมจะแสดงข้อผิดพลาดและให้ลองใหม่

ตารางใหม่เป็น additive: `activity_facebook_uploads`, `activity_facebook_jobs` ไม่แก้ข้อมูลอัลบั้มหรือรูปเดิม

## ตรวจสอบ

`npm ci --ignore-scripts` แล้ว `npm test` (Node 24)

ชุดทดสอบครอบคลุมการเลือกภาพจริง, opt-in รายชุด, จำนวนภาพไม่ครบ, สิทธิ์และ Audience, แบ่งชุด, การทำงานซ้อน, การเชื่อมต่อขาดหลังส่งโพสต์, การลองใหม่ และการไม่เปิดเผย token การทดสอบเครือข่ายใช้ Meta/Drive จำลอง ไม่มีการโพสต์จริงจากชุดทดสอบ
