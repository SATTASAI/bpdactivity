# bpdactivity — ภาพกิจกรรมโรงเรียนบ้านป่าเด็ง

`activity.banpadengschool.ac.th` · Cloudflare Worker + D1 (ฐานเดียวกับ system) + Google Drive

- ทุกคนดูภาพได้ ไม่ต้องล็อกอิน
- ครูล็อกอินด้วยบัญชี system (ต้องมีบทบาทแล้ว) → สร้างงาน + อัพภาพ
- สร้างงาน = สร้างโฟลเดอร์ใน Drive ชื่อ `ชื่องาน (30 ต.ค. 2569)` (วันที่วันสร้างงาน ตามเวลาไทย)
- แก้ชื่องาน/ตั้งภาพปก/ลบงาน: ผู้สร้างงาน หรือ superadmin/executive · ลบภาพ: ผู้อัพภาพนั้นได้ด้วย
- ลบ = ย้ายไปถังขยะ Drive (กู้คืนได้ 30 วัน)
- ซิงก์กับ Drive ทุก 10 นาที (cron): โฟลเดอร์ย่อยใต้ Photo = อัลบั้ม (วันที่ = วันท้ายชื่อ หรือวันที่สร้างโฟลเดอร์), ภาพในโฟลเดอร์และโฟลเดอร์ย่อย 1 ชั้น; เปลี่ยนชื่อ/ลบใน Drive เว็บเปลี่ยนตาม — อัลบั้มที่มาจาก Drive แก้/ลบผ่านเว็บได้เฉพาะผู้ดูแล
- หน้ารวมเรียงงานใหม่สุดไว้บน
- ภาพส่งผ่าน Worker (`/img/:id/thumb|full`) ไม่ต้องแชร์โฟลเดอร์ Drive เป็นสาธารณะ

## ตั้งค่า (ครั้งแรก)
1. `ACTIVITY_DRIVE_FOLDER_ID` อยู่ใน `wrangler.jsonc` แล้ว (โฟลเดอร์ Photo) — แก้ที่ไฟล์นี้ที่เดียว
2. Cloudflare → Worker `bpdactivity` → Settings → Variables and Secrets เพิ่ม Secret:
   - `JWT_SECRET` (สุ่มใหม่ ไม่ต้องเหมือน system)
   - `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN` (ค่าเดียวกับ Worker `banpadeng-school-db`)
3. Deploy (Git integration) → โดเมน `activity.banpadengschool.ac.th` ผูกอัตโนมัติจาก `routes`

ตารางฐานข้อมูล (`activity_albums`, `activity_photos`, `activity_login_failures`) สร้างเองตอนใช้งานครั้งแรก

## แจ้งเตือนอัลบั้มใหม่

เมื่อสร้างอัลบั้มผ่านเว็บ ระบบส่ง School Notify ให้บัญชีครูที่มีสิทธิ์ดูอัลบั้ม พร้อมปุ่มเปิดอัลบั้มและหน้าเว็บภาพกิจกรรม อัลบั้มส่วนตัวแจ้งเฉพาะเจ้าของที่เป็นครู ครูต้องเชื่อมบัญชีและเปิดรับแจ้งเตือนบนอุปกรณ์

การสร้างอัลบั้มบันทึกคิวพร้อมกับข้อมูลอัลบั้ม แล้วส่งผ่านการเชื่อมต่อภายใน Cloudflare ไปยัง School Notify คิวจะลองส่งอีกครั้งเมื่อขัดข้อง ระบบเริ่มส่งจากอัลบั้มที่สร้างหลังอัปเดต ส่วนการแจ้งเตือนเมื่ออัปโหลดภาพใช้การตั้งค่าเดิม

## Face ID / Passkey — Patch 1.2

เข้าสู่ระบบด้วยรหัสผ่านเดิม แล้วเปิด **ตั้งค่า Passkey** เพื่อเพิ่มอุปกรณ์ ครั้งต่อไปกด **Face ID / Passkey** ได้ รหัสผ่านเดิมยังใช้สำรองได้ บัญชีโรงเรียนใช้ Passkey ร่วมกันระหว่าง system, grades, teachingmedia, activity และ publicservice บนโดเมนโรงเรียน

รัน `npm ci` ก่อนทดสอบ/build ตาราง Passkey สร้างแบบ additive ในคำขอแรก ใช้ HTTPS; ไม่มีการเก็บภาพใบหน้า ลายนิ้วมือ หรือ private key

[รายละเอียด วิธีใช้ ขอบเขต และผลตรวจสอบ](https://github.com/SATTASAI/banpadeng-school-db/blob/main/docs/passkeys.md)


## Patch 1.4 — 9 พฤศจิกายน 2569

- มือถือ: bottom bar (หน้าหลัก / อัลบั้ม / อัปโหลด / บัญชี), เมนูอัลบั้มแบบแผงเลื่อนจากล่าง, ปุ่มสัมผัสอย่างน้อย 44px, safe area และระยะท้ายหน้าไม่ถูกเมนูบัง
- กลับจากอัลบั้มแล้วคืนตำแหน่งเลื่อน พร้อมรีเฟรชข้อมูลโดยเก็บหน้าที่โหลดไว้; ฟอร์มจัดการเป็นแผงด้านล่างที่เลื่อนภายในได้ รองรับ reduced motion
- อัปโหลดผ่านเว็บ: แจ้ง School Notify หลังจบแต่ละชุด พร้อมชื่ออัลบั้ม จำนวนภาพสำเร็จ และลิงก์เปิดอัลบั้ม ไม่แจ้งทีละภาพหรือแจ้งอัลบั้มเก่าย้อนหลัง
- ผู้รับเริ่มต้น: บัญชีครู/เจ้าหน้าที่/ผู้บริหาร/ผู้ดูแลที่ active และมีสิทธิ์ดูอัลบั้ม ไม่รวม viewer_accounts; อัลบั้มส่วนตัวส่งเฉพาะเจ้าของกับผู้ดูแล/ผู้บริหาร ต้องผูกบัญชี School Notify ด้วย ref `u:<user id>`
- คิวเก็บใน D1 (`activity_notify_batches`, `activity_notify_deliveries`) อัตโนมัติ ตรวจสิทธิ์ใหม่ก่อนส่ง หากปิดหน้าระหว่างอัปโหลด ระบบส่งหลังไม่มีภาพเพิ่ม 10 นาที; cron ตรวจคิวทุกนาทีและยังซิงก์ Drive ทุก 10 นาที
- ส่งไม่สำเร็จจะ retry แบบเพิ่มระยะห่าง มี lock ป้องกันการทำงานซ้อนและบันทึกผู้รับที่ API ตอบรับแล้ว กรณีเครือข่ายขาดหลังปลายทางรับข้อความแต่ก่อนตอบกลับ อาจได้รับซ้ำได้
- การอัปโหลดตรง Google Drive และอัลบั้มที่ไม่มีภาพใหม่ไม่สร้างแจ้งเตือน

### เปิดใช้การส่งจริง

Cloudflare → Worker **bpdactivity** → Settings → Variables and Secrets: เพิ่ม secret **NOTIFY_API_KEY** ให้มีค่าเดียวกับ **API_KEY** ของ Worker school-notify แล้ว deploy ใหม่ ห้ามใส่ค่า secret ใน Git หรือโค้ดหน้าเว็บ

หากยังไม่มี secret ภาพยังอัปโหลดได้ตามปกติ คิวจะรอส่งหลังตั้งค่าสำเร็จ การรับ push บนอุปกรณ์ยังขึ้นกับการเชื่อมบัญชีและอนุญาตแจ้งเตือน School Notify

### ตรวจสอบ

`npm test`: 14 รายการ ครอบคลุม API เดิม การรวมชุดอัปโหลด ผู้รับตามสิทธิ์ การทำงานซ้อน การ retry การไม่มี secret และอัลบั้มที่ถูกลบ

ทดสอบ DOM สำหรับเมนูอัลบั้ม/บัญชี/อัปโหลด, lightbox, bottom bar และคืนตำแหน่งเลื่อนแล้ว การตรวจภาพจริงบนมือถือยังต้องทดสอบเพิ่ม (สภาพแวดล้อมนี้ไม่อนุญาตเปิด Chromium สำหรับหน้าทดสอบ)
